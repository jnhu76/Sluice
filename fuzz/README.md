# Sluice Fuzz Foundations

Deterministic fuzz testing for the Sluice I/O library, using **Clang libFuzzer**
with **AddressSanitizer + UndefinedBehaviorSanitizer**. No third-party fuzz
frameworks.

The fuzz targets here exercise *production* `sluice_core` code that has been
coverage-instrumented (`sluice_core_fuzz`). The harness models
(`fuzz/support/`) are minimal, observable test-only endpoints — they do **not**
reuse production's `MemoryReader`/`MemoryWriter`, and every target carries an
*independent oracle* that re-derives the expected result from the raw input
bytes without consulting the production code under test.

## Targets

| Target | Production surface | Oracle |
|---|---|---|
| `wal_read_record_fuzz` | `src/wal.cpp` record decode path | Independent WAL layout decoder (`wal_oracle.hpp`) re-derives magic/length/payload/checksum from raw bytes |
| `wal_roundtrip_fuzz` | `src/wal.cpp` write + decode | Byte-identical write encodings; decode round-trips; EOF returns eof |
| `copy_all_fault_fuzz` | `src/copy.cpp` strategy loop | Prefix-integrity, limit-safety, error-propagation, broken-reader rejection (`copy_model.hpp`) |

## Layout

```
fuzz/
  wal_read_record_fuzz.cpp      # WAL decode oracle checks (W1-W5)
  wal_roundtrip_fuzz.cpp        # write_record round-trip checks
  copy_all_fault_fuzz.cpp       # copy_all fault-model checks (C1-C8)
  gen_seeds.cpp                 # one-time deterministic seed generator
  support/
    byte_cursor.hpp             # deterministic total byte-stream decoder
    fuzz_abort.hpp              # FUZZ_ASSERT / fuzz_fail (trap, not signal)
    wal_oracle.hpp              # independent WAL layout decoder
    tracking_reader.hpp         # in-memory Reader tracking max request
    copy_model.hpp              # fault-model Reader/Writer + CopyConfig decode
  corpus/
    wal_read_record/            # committed seeds for wal_read_record_fuzz
    wal_roundtrip/              # committed seeds for wal_roundtrip_fuzz
    copy_all_fault/             # committed seeds for copy_all_fault_fuzz
  dictionaries/
    wal_record.dict             # WAL structure dictionary for the encoder
```

Seeds are content-addressed (SHA-1) and committed. They are generated by
`gen_seeds.cpp`, not by the fuzzer — the fuzzer only *adds* to the corpus at
runtime, never to the committed tree.

## Building

The fuzz targets live behind their own xmake target group (`fuzz`) and a
separate coverage-instrumented static library (`sluice_core_fuzz`) so that
instrumentation never leaks into the production `sluice_core` build:

```sh
xmake f -m debug --toolchain=clang -y
xmake build -g fuzz
```

`sluice_core_fuzz` is built with `-fsanitize=fuzzer-no-link,address,undefined`
and each fuzz executable is linked with `-fsanitize=fuzzer,address,undefined`.
The production `sluice_core` is built **without** instrumentation — it is the
fuzz target that is instrumented, and only the object files that `sluice_core`
and `sluice_core_fuzz` share.

## Running

### Corpus replay (deterministic baseline)

```sh
./build/linux/x86_64/debug/wal_read_record_fuzz fuzz/corpus/wal_read_record -runs=1
./build/linux/x86_64/debug/wal_roundtrip_fuzz   fuzz/corpus/wal_roundtrip   -runs=1
./build/linux/x86_64/debug/copy_all_fault_fuzz  fuzz/corpus/copy_all_fault  -runs=1
```

`-runs=1` replays each committed seed exactly once. This is the deterministic
gate that the mutation proof replays.

### Bounded smoke

```sh
bash scripts/run-wal-copy-fuzz-smoke.sh
```

Replays the corpus, then runs a short bounded random session per target
(120 runs, 30 s, 1 GiB RSS cap). Artifacts go to `fuzz/artifacts/<target>/`
(gitignored).

### Focused iteration

libFuzzer supports case-name filtering via the `SLUICE_TEST_FILTER` env var for
the unit tests; for the fuzz targets, pass a single seed to reproduce:

```sh
./build/linux/x86_64/debug/copy_all_fault_fuzz <seed-file> -runs=1
```

## Mutation proof

`scripts/run-wal-copy-mutations.sh` applies 11 hand-authored mutations
(5 WAL + 6 copy_all) to production source in an **isolated git worktree** and
replays the committed seed corpus for each. A mutant is:

- **KILLED** — any seed crashes it (oracle assertion or sanitizer trip).
- **SURVIVED** — no seed crashes it.
- **INVALID** — the source fragment does not match exactly once (code moved, or
  the mutation fails to build).

The script never edits the caller's worktree: it requires a clean tracked HEAD,
creates a detached worktree at that SHA, and traps cleanup on exit. The current
proof kills all 11 mutants (0 survived, 0 invalid).

```sh
bash scripts/run-wal-copy-mutations.sh
```

## Crash workflow

When a fuzzer finds a crash, the artifact file on disk is the reproducer:

1. Replay it directly: `./build/.../copy_all_fault_fuzz <crash-file> -runs=1`.
2. The oracle assertion (or sanitizer) tells you *which* invariant broke.
3. Convert it to a regression test: add the failing input as a new committed
   seed (it now passes because the bug is fixed) **and** add a focused unit
   test that encodes the invariant directly.
4. Never delete a crash artifact without preserving the reproducer and the
   reason it is no longer a live bug.

Crash artifacts are written to `fuzz/artifacts/<target>/` (gitignored). Seeds
that should be regression-guarded are promoted into `fuzz/corpus/<target>/`
and committed.

## Constraints

- Clang libFuzzer is required; GCC is not supported for these targets.
- ASan + UBSan are required; a sanitizer-clean crash is not a valid reproducer
  until the memory-safety noise is removed.
- Unbounded fuzzing does not belong in normal CI: the committed gate is
  deterministic corpus replay plus a bounded smoke. Long-running fuzzing is a
  separate, scheduled activity.
- Production bug fixes are out of scope for fuzz infrastructure changes. If a
  fuzzer finds a real production bug, file it separately; do not mix the fix
  into a fuzz-tooling PR.
