# Fuzz Corpus Manifest

The committed fuzz corpus under `fuzz/corpus/<target>/` is the **union** of two
kinds of seeds with different origins and purposes:

- **Curated named seeds** — generated by `fuzz/gen_seeds.cpp`. Each is
  hand-authored to encode a specific property, contract boundary, or failure
  mode. Their byte layout is deterministic; running the generator reproduces
  them byte-for-byte (verified by
  `scripts/verify-wal-copy-curated-seeds.sh`).
- **SHA-named coverage seeds** (40-hex-character filenames) — discovered by
  libFuzzer during bounded/random fuzzing and deliberately promoted into the
  committed regression corpus because they add coverage or encode a meaningful
  boundary. They are NOT generated by `gen_seeds.cpp` and are not required to
  be reproducible by it.

The complete committed corpus is the union of both sets. Do not claim all
committed seeds are generated by `gen_seeds.cpp` — the SHA-named seeds are
libFuzzer-discovered.

## `fuzz/corpus/wal_read_record/`

Input shape: `[config byte] [arbitrary byte stream]`. The config byte selects a
short-read cap (1..64) for the tracking reader; the rest is fed to the
production `sluice::wal::read_record()` and compared against the independent
canonical-format oracle.

### Curated named seeds (generated by `gen_seeds.cpp`)

| filename | intended property |
|---|---|
| `empty` | empty input — oracle not-decoded, production eof |
| `one_byte` | config byte only, no stream |
| `truncated_header` | 6 of 8 header bytes present |
| `valid_empty_record` | complete record, zero-length payload, valid checksum |
| `valid_one_byte_record` | complete record, one-byte payload |
| `valid_binary_record` | payload contains 0x00 and 0xFF |
| `bad_magic` | magic field flipped |
| `bad_checksum` | valid frame, corrupted checksum byte |
| `truncated_payload` | declared length > present payload bytes |
| `truncated_checksum` | payload complete, checksum missing last byte |
| `huge_declared_length` | length = 0xFFFFFFFF, no payload |
| `two_records` | two valid concatenated records (trailing ignored) |
| `record_plus_garbage` | one valid record then unrelated trailing bytes |

### SHA-named coverage seeds

origin: libFuzzer-discovered
purpose: coverage/regression (no single named property)

## `fuzz/corpus/wal_roundtrip/`

Input shape: raw payload (the harness does not discard bytes). For every
payload it requires scalar/vector byte-identical encodings, canonical-format
validity (via the independent oracle), production decode round-trip, and clean
EOF after exactly one record.

### Curated named seeds (generated by `gen_seeds.cpp`)

| filename | intended property |
|---|---|
| `empty` | zero-length payload (empty record) |
| `one_byte` | single-byte payload |
| `binary_00_ff` | payload with 0x00 and 0xFF |
| `counting_256` | 256-byte counting payload (boundary at u8 wrap) |

### SHA-named coverage seeds

origin: libFuzzer-discovered
purpose: coverage/regression

## `fuzz/corpus/copy_all_fault/`

Input shape: `[config] [source payload]`. The config is decoded by
`fuzz::decode_config()` (see `fuzz/support/copy_model.hpp` for the binary
layout); the unconsumed tail is the COMPLETE source payload (the harness
performs no silent truncation — resource bounds live in the runner's
target-specific `-max_len`).

### Curated named seeds (generated by `gen_seeds.cpp`)

| filename | intended property |
|---|---|
| `empty_source` | empty source, Auto, unlimited, scratch 64 |
| `one_byte_source` | single-byte source |
| `large_source` | 256-byte source, scratch 8 (multi-iteration short reads) |
| `zero_limit` | CopyLimit::nothing() — endpoints never touched |
| `limit_smaller` | bounded limit < source size |
| `limit_equal` | bounded limit == source size |
| `limit_larger` | bounded limit > source size |
| `empty_scratch` | scratch size 0 with non-zero copy → invalid_state |
| `reader_fail_before_first` | AfterCalls(0) reader failure |
| `reader_fail_after_prefix` | AfterCalls(2) reader failure after a prefix |
| `writer_fail_before_first` | AfterCalls(0) writer failure |
| `writer_fail_after_prefix` | AfterBytes(5) writer failure after a prefix |
| `one_byte_short_reads` | reader_short = 1 |
| `one_byte_short_writes` | writer_short = 1 |
| `broken_reader` | broken-reader over-report (got > requested) |
| `deferred_reject` | VectorDeferred + ReturnInvalidState |
| `deferred_fallback` | VectorDeferred + FallbackToAuto |
| `binary_source` | source with 0x00 and 0xFF |
| `buffered_full` | BufferedReadable prefix fully satisfies unlimited Auto copy |
| `buffered_then_scratch` | buffered prefix then scratch tail (CB5 transition) |
| `buffered_limit_smaller` | buffered + bounded limit < prefix (M-COPY-07 killer) |
| `buffered_scratch_strategy` | Scratch strategy with a buffered reader (no peek/consume) |
| `buffered_writer_fail` | BufferedFirst, writer fails draining buffered bytes (CB3 / M-COPY-08 killer) |
| `buffered_consume_fail` | consume_buffered fails after a successful write (CB6) |
| `source_beyond_4096` | 5000-byte source (bytes past offset 4095 participate in the oracle) |
| `writer_zero_progress` | write_some returns 0 on non-empty input (§20.1) |
| `early_eof_before_first` | empty source → clean EOF before any byte (§20.2) |
| `early_eof_after_prefix` | early clean EOF after 5 bytes though more remain (§20.2) |

### SHA-named coverage seeds

origin: libFuzzer-discovered
purpose: coverage/regression

## Promotion policy

A newly discovered SHA-named seed is promoted into the committed corpus only
when it:

- reproduces a real defect;
- kills a previously surviving mutant;
- adds demonstrable coverage or a meaningful boundary; or
- is a minimized form of an existing regression.

Promotion requires a written reason (add it to this manifest or the evidence
document). Do not regenerate or delete SHA seeds merely to make the corpus
prettier; do not delete named semantic seeds merely because libFuzzer regards
them as coverage-redundant (they encode human-readable contract boundaries).
