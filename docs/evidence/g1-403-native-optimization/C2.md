# G1 C2 — Occupancy experiment: the outstanding summary counter (mechanism A)

Status: controlled experiment (arm C2-A), mechanism A of the risk-ordered
list. Baseline for the arm: commit `4c86d3fe` (C9-A + C1-A adopted).

## 1. Target (measured)

`RequestCore::occupancy()` scans every slot under `mutex_`
(request_core.cpp:34-59) and is invoked:
- once per progress pass for `accepted_work_remains` (both backends read
  only `.outstanding`);
- once per submit for the `update_max_outstanding` stat via
  `backend_->outstanding()`;
- at settlement (`settlement_converged_`), shutdown, and destruction checks
  (full-occupancy consumers, unchanged).

The PMU campaign sampled `occupancy` at **1.13%** of cycles (direct, W-02-TP-w4)
before counting its mutex share; the per-pass scan also lengthens the
`mutex_` critical section other threads contend on.

## 2. Mechanism A (implemented): mutex-scoped derived counter

`std::size_t outstanding_` in RequestCore, plus
`std::size_t outstanding_summary() const noexcept` (mutex-scoped read).
`occupancy()` remains the authority; only the two non-settlement consumers
switch to the summary.

Update points — exhaustive by construction, because `outstanding` is the
count of slots with `phase == accepted && !published`, and the code has
exactly two sites that move a slot into or out of that set, both inside
`mutex_`:
- `accept` (request_core.cpp:189 region): slot becomes accepted-unpublished
  → `++outstanding_`;
- `complete_publication` (:465 region): `published = true` → `--outstanding_`.

Every other transition leaves the set invariant:
- `rollback` releases a *reserved* slot (never counted);
- `reclaimable_` requires `published`, so every `try_reclaim_`/`release_slot_`
  caller (audit: request_core.cpp:83,213,284,333,400,427,474,535,540,562)
  releases only published or reserved slots — never an accepted-unpublished
  one;
- generation exhaustion (:598) is reached only from `release_slot_`.

Therefore `outstanding_ == |{accepted ∧ ¬published}|` at every `mutex_`
release; divergence is impossible without a code change outside the two
sites, and both the counter and the scan read the same lock-protected state.

## 3. Required invariants and how this arm satisfies them

| invariant | status |
|---|---|
| accepted/released/reclaimed conservation | transition set untouched; only a summary added |
| public_bindings / execution_refs / control_refs / publication_inflight / observer_registrations | untouched (still scan-computed in `occupancy()`) |
| no overflow/underflow | `++` exactly at the state-entry site, `--` at the state-exit site; same-lock serialization ⇒ the counter tracks a 0..capacity population |
| terminal/reclaim conditions unchanged | `reclaimable_` and all verdict paths untouched |
| shutdown not completing on stale counts | settlement keeps using the full `occupancy()` scan (`settlement_converged_`, destroy checks) — the counter is never consulted there |
| visibility/linearization | counter reads/writes happen under the same `mutex_` as the transitions they summarize; a summary reader observes a value some completed critical section produced |
| not a second source of truth | the counter is derived, named `outstanding_summary`, documented as non-authoritative; `occupancy()` remains the authority and disagrees only if the update sites are edited |

## 4. Evidence obligations

- Regression floor: RequestCore protocol/publication/ownership suites,
  threadpool/uring cutover suites, progress race suites, shutdown, backend
  conformance, app oracles (the full test group).
- Paired A/B of arm C2-A vs the adopted arm (C9-A + C1-A) on the decision
  cases, then the final combined arm vs B0 (with 15 repetitions on
  `W02-threadpool-4k-d16-w1` for the disclosed regression follow-up).
- Decision rule: adopt iff no regression beyond case noise on any decision
  case (the expected effect is small: removing a 16-slot scan per pass and
  per submit); a flat result is acceptable only if nothing regresses —
  otherwise revert and record `C2_NO_SAFE_CHANGE`.

## 5. Verdict (post-experiment)

**ADOPTED.** All 61 test targets green (release, liburing=y). Increment A/B
vs the adopted arm (`ab/c2/AB.md`): W02-threadpool-4k-d16-w4 +1.6% (paired
spread crosses 1 — noise-level), W03-threadpool-4k-d16-w4 +6.5%, W02-uring
+9.1% (cross-binary layout noise; the mechanism cannot add anything to the
uring submission path, and the spread 0.91..1.24 confirms it). No decision
case regressed; the settlement and destruction consumers still read the
authoritative `occupancy()` scan.

A companion candidate measured in this phase was **rejected**: skipping the
pre-park drain when no kernel writer is armed (using the registration fact
to prove the counter empty) showed no benefit (w1 −2.7%, w4 −3.0% vs armC,
`/var/tmp` scratch only) and added a mechanism; reverted per the
no-speculative-mechanism gate. The w1 regression disclosed in `ab/final`
is therefore a C9-A park-cycle effect, not a drain-cost effect.
