- missing_increment: exit 142 = the suite's internal `::alarm(120)`
  watchdog; the parity oracle (counter 0 != expected 1 at the first

  the case's Fixture teardown then deadlocks in
  AsyncIoContext::drive_settlement_ because the gated sweep can no longer
  see the owed events, so the FAIL line is never reached. Independently
  confirmed by gdb attach during the hang: main parked in poll() under
  ProgressSource::wait_if_unchanged/drive_settlement_, worker parked in
  work_cv_ (pthread_cond_wait) — same shape as the round's original gdb
  evidence. Contract: increment pairing + settlement liveness.
- missing_decrement: exit 1 at the first case's post-delivery quiescent
  check (counter 3 vs exact scan 0 vs expected 0). Contract: decrement
  pairing with each collected event.
- empty_verdict_always: the six counter-parity cases stay green (the
  mutant only affects the verdict), then exit 1 at
  owed_during_pass_is_counted_and_reported because an owed event produced
  between sweep and verdict must set immediate_work_remains. Contract:
  PROG-01 honest residue verdict.
- reclaim_ignoring_control_refs: exit 134 via the fail-fast inside
  slot_reuse_before_delivery_keeps_parity (slot freed while the owed
  control reference still pins it). Contract:
  event_owed => control_refs >= 1 => !reclaimable_.
- All four kills are runtime oracle kills (no compile-failure
  substitutions). Normal build restored and green (8/8) after the runs.
