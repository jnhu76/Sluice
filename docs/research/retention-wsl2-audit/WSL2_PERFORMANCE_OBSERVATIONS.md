## 4. Method

1. Correctness oracle first (untimed single runs of every arm on both
   binaries).
2. A/A noise floor: `ladder-cand` vs itself, ABBA interleaved, 16 pairs (32
   samples) per series, analyzed order-aware (`analyze2-p5.py --order`);
   acceptance: median ≈ 0, balanced signs, CI95 straddling 0.
3. A/B: `ladder-cand` vs `ladder-base` with the same ABBA/order-aware
   discipline; per-pair statistic is `ladderA − ladderB`; negative favors the
   candidate (master).
4. Size sweep 0 B / 1 B / 64 B / 512 B / 4 KiB / 64 KiB ×
   `read_exact_at (ax)` / `read_exact (ac)` / `write_all_at (wx)` /
   `write_all (wc)` under the P1 preregistered ops/warmup table (0–512 B →
   ops=4096 warmup=4096; 4 KiB → 1024/1024; 64 KiB → 512/512), reps=5,
   16 pairs, plus the non-composed negative control `read_at (a2)` at 4 KiB
   which must stay parity.
5. User/kernel cost separation via the ladder's per-sample `getrusage` split
   (`user_ns_per_op`/`sys_ns_per_op` on every emitted line) plus coarse
   whole-process `/usr/bin/time -v` records.
6. Coarse cross-check with the in-tree `bench_w01_direct` group.

## 5. Correctness oracle

Every timed or untimed ladder invocation runs the kit's built-in content
oracle: destinations are poisoned with the inverted expected pattern, and any
byte mismatch prints `VERIFY_FAIL` and exits non-zero, which aborts the whole
`paired2.sh` series (`set -euo pipefail`). Results:

- Smoke runs of all arms (`ax`, `ac`, `a2`, `a1x`, `a1c`, `wx`, `wc`, `w1x`,
  `w1c`, `ax tail`) on both binaries: exit 0 on every arm.
- Write arms additionally read the whole scratch file back and emit
  `content_ok=1` (verified); the readback content hash
  `0xa2a7b385a4908383` is identical across both sides.
- Read arms emit `content_ok=-1` (field n/a by design; the poisoned-buffer
  verify pass enforces correctness through the exit code instead). This
  matches the archived E5 caliber exactly (`ab-comp-read-4k.txt` shows the
  same `content_ok=-1` lines), so the field semantics were not reinterpreted.
- Every one of the 1,152 paired-series process invocations (5 A/A + 7 A/B 4K
  + 24 sweep series, 32 samples each) exited 0, as did the 15 oracle smokes —
  the oracle passed on every sample of both sides. No correctness regression
  was observed anywhere.

The read arms establish a clean floor. The write arm demonstrated a
false-positive mode: two outliers (~600 ns) in run 1 pushed the CI off zero
for the *same binary against itself*, and the rerun drifted the other way
(median +19.9 ns, signs 11/16). Recorded fresh minimum-detectable-effect
estimates (2.131·sd/√16):

- read seq 4 KiB: sd ≈ 189 ns → MDE′ ≈ 101 ns
- read eofmix 4 KiB: sd ≈ 25 ns → MDE′ ≈ 13 ns
- read_exact 4 KiB: sd ≈ 49 ns → MDE′ ≈ 26 ns
- write arms: sd 86–198 ns → MDE′ ≈ 46–106 ns, with documented sign-flipping
  drift and a demonstrated CI-excluding A/A false positive.

Consequence applied below: a CI-excluding cell inside the write family is not
accepted as a distinguished difference unless it replicates across independent
same-parameter series.

## 8. User/kernel cost separation

Two calibers were recorded (receipts §7):

- Per-sample `getrusage` split emitted on every ladder line (window covers
  warmup + timed reps + read verify; the write-scratch 64 MiB prime and
  readback run outside it). Pooled medians over each series' 32 samples:
  read arms at 4 KiB ≈ 660–685 ns sys vs ≈ 370–400 ns user; 64 KiB reads
  ≈ 10.7–10.8 µs sys vs ≈ 4.9–5.1 µs user; write arms ≈ 707–1000 ns sys vs
  ≈ 0–12 ns user at ≤4 KiB, and ≈ 12.3–12.6 µs sys vs ≈ 0 user at 64 KiB.
- Coarse whole-process `/usr/bin/time -v` (ops=4096, warmup=4096, reps=20):
  reads user 0.01–0.02 s vs system 0.08–0.11 s; writes user 0.17 s vs system
  0.15 s (the user component there includes the untimed prime pattern fill
  and readback hashing).

Caveat: `getrusage` tick granularity on this kernel frequently rounds one of
the two components to 0.000 on short windows, so the split is qualitative:
all observed ops are syscall-dominated on both sides, with master/base
showing the same composition. No per-op user/kernel regression asymmetry was
observed.

## 9. PMU status

`perf` exists on the guest. Probes (receipts §8):

- `perf stat -e cycles,instructions sleep 0.3`: rc=0, user-mode counters
  counted (cycles:u ≈ 2.7M, instructions:u ≈ 2.0M).
- `perf stat -e cycles:k sleep 0.2`: refused, rc=255 — kernel profiling is
  blocked by `perf_event_paranoid = 2`.
- Plain `perf stat -e cycles` silently degrades to `cycles:u`.

pmuStatus = **PARTIALLY_OBSERVABLE_USER_ONLY**: user-space counting works,
kernel-inclusive PMU observation is not available on this guest, and no
hardware-counter accuracy validation beyond plausibility was possible. No PMU
counts were used in any verdict; all statistics are wall-clock paired.

## 10. In-tree bench cross-check (coarse)

`bench_w01_direct` was built in both worktrees (bench source sha256 identical:
`e53b8331…9ba5ad`) and run for `W01-read_exact_at-4k` and
`W01-write_all_at-4k` (7 measured reps of 50000 ops per run; warmup=16, a
disclosed deviation from the reference's 64, to bound wall time).

- Fixed-order interleave m,b,m,b showed master at −3.6 %/−6.1 %/−5.3 % ops/s
  across three read pairs.
- Re-running the same case with reversed order b,m,b,m (ABBA) flipped the
  sign: master +5.4 %/+3.7 %/+6.1 %.
- The write case showed no consistent direction either way
  (+3.6 %, +5.4 %, −2.5 %).

Conclusion: the in-tree bench carries a ~±5 % run-position bias on this host;
its sign tracks execution position, not binary identity. It is retained as a
no-signal coarse observation and is consistent with the formal paired ladder's
parity. This is precisely the order bias the archived `paired2.sh` ABBA
schedule exists to cancel.

## 11. Verdict

- Correctness: the kit's content oracle passed on every sample of every
  series on both sides; no correctness regression.
- Performance: no distinguishable speedup or regression between the candidate
  (`84e1b7d5`, C1+P2C1) and the baseline (`77e5399a`, C1 only — PR #602
  branch head) on this WSL2 host across 4 ops × 6 sizes, 16-pair ABBA
  series, order-aware analysis, with the negative control at parity and the
  single flagged write cell resolved as noise (§7). The measured increment is
  the P2C1 (#612) change alone; C1 is present on both sides, so this
  comparison does not isolate C1's WSL2 wall-clock effect.

## 12. Caveats and limitations

1. Write-family noise: A/A run 1 produced a CI-excluding result on identical
   binaries; write-arm MDE′ is 46–106 ns and the single flagged sweep cell
   failed replication across two further same-parameter series. All write-arm
   judgments below ~100 ns/op remain indistinguishable by evidence, not proven
   equal.
2. `cpu2` frequency/governor is not observable in this WSL2 guest (no cpufreq
   sysfs), so CPU frequency state during series is UNKNOWN; pinning and ABBA
   interleaving mitigate but do not eliminate frequency drift.
3. getrusage tick granularity makes the per-op user/sys split qualitative
   (one component often 0.0); `/usr/bin/time -v` records are whole-process
   and include untimed prime/readback work.
4. PMU observation is user-mode only; kernel-inclusive counters blocked
   (`perf_event_paranoid = 2`).
5. The in-tree bench comparison ran with `SLUICE_BENCH_WARMUP=16` (reference
   specified 64) and is position-bias dominated; it is not used as evidence of
   any difference.
6. Scope of the observed delta is the four composed ops plus the non-composed
   control across six sizes; other workloads (vectored, planner, copy arms)
   were not observed in this round and are not claimed.
7. The ladder's read-arm `content_ok=-1` field semantics are instrument
   design (verification via exit code), confirmed against the archived E5
   outputs, not a skipped oracle.
8. Attribution boundary: baseline `77e5399a` is the PR #602 branch head and
   already contains C1 (code commit `4c3e698d`, squash-merged to master as
   `43cb8029`), so the A/B isolates only the P2C1 increment. C1's standalone
   WSL2 wall-clock effect was never measured here (a pre-C1 baseline such as
   `43cb8029^` = `ac995641` was not built); `77e5399a` is not an ancestor of
   `origin/master` (merge-base `bdfd0d8d`) and remains reachable via
   `refs/pull/602/head` and the backup branch.
