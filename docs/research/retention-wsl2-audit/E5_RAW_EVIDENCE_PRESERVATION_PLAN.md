## 3. Special evaluation: can `baseline/disk-fixture/` be deterministically rebuilt?

**Question:** can the 1.35 GB of 64 MiB fixtures ("data, not results",
evidence-index §2) be regenerated byte-identically from a frozen script +
seed + inputs + checksums, so the archive can carry the recipe instead of the
bytes?

**What the in-tree record establishes:**

- `baseline/disk-fixture/` = 10 top-level files, 1,353,326,592 bytes, described
  only as "64 MiB fixtures on btrfs (data, not results)"
  (evidence-index §2, line 45).
- The harness consumes a fixture location via `SLUICE_BENCH_TMP_DIR` (default
  `/tmp/sluice-bench`) — see `bench/research/key-path-593/harness/
  baseline-run_stage.sh` (`tmpdir="${5:-}"` → `export SLUICE_BENCH_TMP_DIR`),
  but **no script that creates the fixtures is committed**.
- `git grep -n -iE "disk-fixture|fallocate|mkfs\.btrfs|truncate -s"
  origin/research/593-key-path -- 'bench/research/key-path-593'
  'docs/research/key-path-593'` returns only the three evidence-index
  mentions (receipt 06): **no generator, no seed, no byte-pattern spec.**
- `baseline/SHA256SUMS.txt` exists on the host (its SHA-256,
  `3156ec13bc2ae33a14b9fb2b880b64b14a461acf14106acf066d2e7d79fa9c36`, is
  recorded in evidence-index §6) but its **coverage of the fixture files is
  unverified** — it may cover only summaries and identities.

**Verdict: NOT demonstrably rebuildable today → treat the fixtures as
irreplaceable input data and include them in the archive.** Deterministic
rebuild would require all four of: (a) a frozen generator script committed
in-tree, (b) a fully determined content derivation (fixed seed or fixed byte
pattern — no host entropy, no uninitialized `fallocate` holes counted as
content unless the reader is proven hole-insensitive), (c) recorded generation
inputs (filesystem btrfs, target paths), and (d) per-file SHA-256 of the
archived fixtures to prove equality. None of (a)–(d) is currently in the tree.

**Verification command set (to run on E5 when accessible; read-only except the
`/tmp` regeneration):**

```sh

grep -rnl --include='*.sh' -e 'disk-fixture' -e 'fallocate' -e 'truncate -s' \
```
