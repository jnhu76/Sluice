# #595 R4 图注（每图四句：观察到什么 / 哪个对照支持什么 / 哪些因果未识别 / 工程影响）

所有差值均来自 `analysis/MAIN_SUMMARY.json`（配对 tuple、bootstrap 10000/seed 5950、
单侧 95% 界）；原始数据 `raw/matrix`、`raw/extension`、`raw/diagnostics`。图中正=更差。

## F1 净效果与适用范围（`F1_net_effect.svg/pdf/png`）

1. 观察到：W03-d16 主形状上 R−A0 CPU/op 点估计 −19.6%（单侧上界 −19.1%）、S−A0
   −12.8%（−12.4%），吞吐分别改善 24.5%/14.8%；但 R 的 p99 上界 +23.6%、S 的 p95/p99
   上界 +34.7%/+36.3%，均越过 +5% 尾延迟界。
2. 支持什么：R−A0 与 S−A0 两臂的 CPU/吞吐条件在 W03-d16 成立（点估计 ≤−10%、上界
   ≤−5%、吞吐上界 ≤+3%）；尾延迟条件不成立，因此主门按 §7.1 合取判 FAIL（R 仅 p99，
   S 为 p95 与 p99）。其余核心格只给保护界：W03-d4 上 R/Q8 的全部指标在界内而 S 的
   p99 超界（上界 +19.4%）；W03-d64（R/Q8/S 的 p99、S 的 p95）、W03-d2serial（R/S/Q8
   全部指标）与 W02 系（个别 CPU/吞吐/p99 成员）有超界（见 F3/逐格表）。
3. 未识别：本图不能把 CPU 收益归因于 enter 合并本身——没有拆分 submitter/driver 的
   受控实验，CPU 分桶残差 22–26% 未归因；也不能解释尾延迟回归的机制来源（排队/提交
   批次/完成顺序）——需独立诊断。W03-d16 无 strace enter 直方图，不能反推 caller
   ready-span 分布。
4. 工程影响：若以 CPU/吞吐为目标，R 在 d16 有显著净收益；若 SLA 含 p99，R/S 的尾延迟
   回归（+22%～+36%）会抵消收益，主门失败。TRAJECTORY 因 0/24 INCOMPLETE 未画入本图。

## F2 信息是否改变行为（`F2_behavior_change.svg/pdf/png`）

1. 观察到：d16 上 S 的决策 99.92% 落在 completion_pressure 行、99.97% 选择 quantum=2，
   ready 均值 7.92 而实际呈现均值 2.00（present/ready=25.2%）；对照 R 的动作（SHADOW
   记录）呈现 100% ready、接受率 68.6%。
2. 支持什么：以 SHADOW 反事实（同一决策点的 S 表动作 vs R 实际动作）比较，d16 上
   99.95%、T2 上 100%、T3 上 99.97% 的决策动作会改变——信息确实改变行为，故明确
   不是 NO_ADDITIONAL_STATE_EXPOSURE。T1（稀疏单条）改变率 0%：remaining==1 已强制
   两策略同为 immediate，这是唯一动作完全相同的形状。
3. 未识别：诊断行不给出「若采用 S 动作则 enter 数/延迟会怎样」的因果反事实——SHADOW
   只记录动作选择，不执行它；enter 直方图不能反推 caller 分布（W03-d16 也没有 enter
   直方图，prereg §10.5 的 strace 对账未跑）。
4. 工程影响：S 的表在 d16/T2/T3 上把批量从整跨度压到 2，呈现次数从 0.125/op
   升到 0.500/op（约 4×）；这解释了 S 相对 R 的 CPU 与尾延迟劣势（S−R +8.5% CPU、
   p99 +10.5%），即「感知」方向在本负载上反而不利。

## F3 分解与消融（`F3_decomposition.svg/pdf/png`）

1. 观察到：W03-d16 上 S−R CPU +8.51%[+7.60,+9.48]、p99 +10.52%（上界 +11.63%）；
   S−Q8 +7.98%、S−Q2 +0.83%、S−SNI +1.21%、S−SNP +3.89%；SHADOW−R（纯读取成本）
   +1.02% [−0.02,+2.10] CPU、p99 +1.22%；R−B 补充块 CPU +9.04%、p95 +32.2%、
   p99 +14.5%（B 比 R 差）。
2. 支持什么：S 的额外状态读取本身（SHADOW−R）只值 ~+1% CPU，而改变动作（S−R）值
   +8.5%——差距主要来自「表选的 quantum=2」而非「读 hint」；S vs 固定 quantum 的
   比较显示 S≈Q2（+0.83%），远差于 Q8（+7.98%），与 TABLE_OVERHEAD_FLAG（S−Q8
   CPU 上界 +8.70% > +3%）一致。
3. 未识别：各对比的基准不同（R、Q2、SNI、SNP、Q8、B 的二进制/块不同），百分比不能
   相加，也不能用百分位差反推阶段分解；R−B 来自独立描述性补充块（同一二进制、
   24 blocks），与主块不可跨块混合。
4. 工程影响：若要保留 R 的收益并提升 S，最直接的杠杆是放宽 quantum 下限（避免被
   pressure/inflight hint 夹到 2）；「感知」表本身没有带来正价值，反而引入尾延迟，
   应作为 negative result 记录而非产品候选。

## F4 CPU—尾延迟散点（`F4_cpu_tail.svg/pdf/png`）

1. 观察到：绝对量上 W03-d16 的 A0 为 3112 ns/op、p99 51.9 µs；R 2501 ns/op、63.2 µs；
   S 2713 ns/op、69.8 µs；Q8 2513 ns/op、64.0 µs；d2serial 的 A0 高达 12916 ns/op
   但 p99 仅 18.3 µs，d64 的 A0 p99 达 181 µs。
2. 支持什么：CPU 与尾延迟在本数据上不是同向权衡——W03-d16/W03-d64 的批量臂 CPU 更低
   但 p99 更高（R/Q8/S 都在右下方向），W02 系则 CPU 略高、尾延迟几乎不变；这支持
   「批量呈现降低 CPU、抬高尾延迟」的跨格模式，但不构成因果证明。
3. 未识别：绝对量跨 case 不可比（fixture/depth/工作负载不同），本图只作形状对照；
   尾延迟升高的物理机制（SQ 批提交的完成顺序、cap 截断、io-wq 唤醒）未被识别；
   p99 是 rep 内分位数均值，不是逐请求 ECDF（未保存逐请求延迟）。
4. 工程影响：R 在 d16/d64 用 ~20% CPU 换 ~20–25% p99 恶化；对尾延迟敏感的部署不应
   只依据 CPU 选择 R；对 CPU 受限、尾延迟不敏感的场景 R 有明确空间。

## F5 状态变化轨迹时间轴（`F5_trajectory.svg/pdf/png`）

1. 观察到：T1→T2→T3 的 S 决策状态显著变化（mean ready 1.00 / 8.36 / 7.92；mean
   present 1.00 / 2.04 / 2.00；quantum=2 份额 0% / 98.9% / 99.97%）；描述性配对差
   在 T1 为 R−A0 +7.49%、S−A0 +12.13%，T2 为 R−A0 −25.86%、S−A0 −8.61%、S−R
   +23.47%，T3 为 R−A0 −20.30%、S−A0 −12.46%。
2. 支持什么：状态确实随轨迹段变化（T1 无批量机会→T2/T3 强 completion pressure），
   且 S 的动作随状态从 immediate 切到 quantum=2；但 **TRAJECTORY 为 0/24 valid
   blocks（INCOMPLETE）**——SHADOW-T1 在每块 3/3 尝试均因 shadow_outstanding_sum==0
   失败，故这些数字只作描述，不进入 F-VALUE/任何门槛。
3. 未识别：无法把 T2 的 S−R +23% 归因到「状态切换」本身（T2 只有 64 读/rep、p95/p99
   分位粗、CPU 分桶残差大）；也无法区分段效应与 case 结构差异（T2 与 T1/T3 的 case
   不同）；SHADOW-T1 缺数据使 T1 的读取成本不可测。
4. 工程影响：即使忽略 INCOMPLETE，轨迹也显示 T2 形状上 S 的劣势最大（S−R +23.5%
   CPU、p99 +65%），提示状态感知策略在最需要自适应的突发场景反而最差；该结论只能
   作为后续轮次的假设，不能作为本轮判定。
