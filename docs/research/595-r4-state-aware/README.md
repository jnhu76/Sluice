# #595 R4: state-aware submission scheduling — native E5 experiment archive

Round R4 asked whether existing request-core information can drive a
no-active-waiting submission policy that reduces full-task CPU without
regressing full-request tail latency, and whether state awareness adds value
over plain suffix batching. Verdict: negative — keep the product on the
immediate per-item path (A0). R (READY_REUSE suffix re-entry) is a real
CPU/throughput result (W03-d16 CPU −19.6%, tput ~+24.5%) that fails the
frozen +5% p99 protection bound (+23.6% one-sided upper); S (STATE_AWARE)
adds no value over R and fails p95/p99. No product code changed; research
worktree only (`research-595-r4` @ f3b25329, implementation patch included).
