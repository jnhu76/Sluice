# WAL + copy_all Fuzz & Mutation Evidence

This document records the evidence for the fuzz testing foundation and the
deterministic mutation proof for the WAL decoder and `copy_all` surfaces.

All commands were run on the `test/fuzz-foundation` branch at the commit noted
in each section. Toolchain: **Clang 21.1.8**, xmake 3.0.9, libFuzzer +
ASan + UBSan, Linux x86_64.

## 1. Coverage instrumentation

The production `sluice_core` sources are compiled twice:

- `sluice_core` — the production static library, **no** sanitizer or coverage
  flags. This is what tests and downstream targets link.
- `sluice_core_fuzz` — the same sources, built with
  `-fsanitize=fuzzer-no-link,address,undefined -fno-omit-frame-pointer`. The
  fuzz executables link this and add `-fsanitize=fuzzer` at link time.

This guarantees the code the fuzzer drives is byte-identical to production
source, coverage-instrumented, and that no instrumentation leaks into the
production library.

Evidence (configuration):

```
xmake f -m debug --toolchain=clang -y
xmake build -g fuzz
```

`xmake/fuzz.lua` defines `sluice_core_fuzz` and the three fuzz targets; the
instrumentation flags are set there, not on `sluice_core`.

## 2. Independent oracles

Each fuzz target carries an oracle that does **not** consult the production
code under test:

- `wal_read_record_fuzz` — `fuzz/support/wal_oracle.hpp` re-implements the WAL
  layout (magic / length / payload / checksum) from scratch and compares the
  production decode against the independently-derived result.
- `wal_roundtrip_fuzz` — checks that the two write encoders are byte-identical,
  that decode round-trips, and that EOF returns eof. The oracle is the
  round-trip invariant itself.
- `copy_all_fault_fuzz` — `fuzz/support/copy_model.hpp` is a minimal
  observable Reader/Writer; the oracle checks prefix integrity, limit safety,
  error propagation, and broken-reader rejection against the raw input bytes.

## 3. Deterministic seeds exercise meaningful properties

Seeds are generated by `fuzz/gen_seeds.cpp` (not by the fuzzer) and committed
under `fuzz/corpus/`. Each seed is crafted to exercise a specific property:

- WAL seeds: valid records, boundary lengths, checksum edge cases, truncated
  payloads, oversized lengths, zero-length payloads.
- copy_all seeds: empty scratch, limit-smaller-than-source, writer-fail after a
  prefix, broken-reader over-report, each strategy, zero limit.

Corpus replay is deterministic (`-runs=1`):

```
./build/linux/x86_64/debug/wal_read_record_fuzz fuzz/corpus/wal_read_record -runs=1
./build/linux/x86_64/debug/wal_roundtrip_fuzz   fuzz/corpus/wal_roundtrip   -runs=1
./build/linux/x86_64/debug/copy_all_fault_fuzz  fuzz/corpus/copy_all_fault  -runs=1
```

Result: all seeds pass (18 wal_read_record + 10 wal_roundtrip + 38 copy_all_fault).

## 4. Mutations are killed

worktree** (never the caller's worktree) and replays the committed seed
corpus. A mutant is KILLED if any seed crashes it.

## 5. No crash without a preserved reproducer

The only crash encountered during development was a heap-buffer-overflow on
corpus replay of the non-mutated binary, on seed `0f7fb248...` (broken-reader
config). Root cause: the production source `src/copy.cpp:204` had been
accidentally mutated to `if (false && got > to_read)` — the M-COPY-05 mutation
leaked into the real source tree. The mutation script is worktree-based and
never touches the caller's worktree, so this was an accidental manual edit.

Fix: restored `src/copy.cpp:204` to `if (got > to_read)` (the committed state).
This is **not** a production bug fix — it is undoing an accidental mutation.
After restoration, all 66 seeds replay cleanly on the non-mutated binary, and
the M-COPY-05 mutant is killed by the broken-reader seed as intended.

No crash artifact was discarded without preserving the reason: the crash seed
`0f7fb248...` remains in the committed corpus and now passes.

## 6. No production fixes mixed in

`git diff HEAD -- src/` is empty for the final state. The only source-tree
change to production code was the *restoration* of `src/copy.cpp:204` to its
committed state. No production bug fix, no API change, no async change.

## 8. Residual notes

- The fuzz targets are Clang-only; they are not built by other toolchains.
- The committed gate is deterministic corpus replay plus bounded smoke.
  Unbounded fuzzing is a separate, scheduled activity and is not part of CI.
- The mutation set is fixed and hand-authored. It is not an unbounded mutation
  framework. Adding a new production invariant should come with a new mutation
  and a new seed that kills it.
