## 1. Coverage instrumentation

The production `sluice_core` sources are compiled twice:

- `sluice_core` — the production static library, **no** sanitizer or coverage
  flags. This is what tests and downstream targets link.
- `sluice_core_fuzz` — the same sources (via the shared `core_sources()` manifest
  in `xmake/libraries.lua`), built with
  `-fsanitize=fuzzer-no-link,address,undefined -fno-omit-frame-pointer`. The
  fuzz executables link this and add `-fsanitize=fuzzer` at link time.

This guarantees the code the fuzzer drives is byte-identical to production
source, coverage-instrumented, and that no instrumentation leaks into the
production library. The `xmake/fuzz.lua` Clang-only guard (`on_config`) raises a
clear configuration error when a fuzz target is requested with a non-Clang
compiler, rather than relying on the sanitizer flags failing later.

```
xmake f -m debug --toolchain=clang -y
xmake build -g fuzz          # builds sluice_core_fuzz + 3 fuzz executables
```

GCC production builds are unaffected:

```
xmake f -m debug --toolchain=gcc -y
xmake build sluice_core      # PASS
xmake build -g test          # PASS
# xmake build -g fuzz        # BLOCKED by the Clang-only guard (intended)
```

## 2. Independent oracles

Each fuzz target carries an oracle that does **not** consult the production code
under test:

- `wal_read_record_fuzz` — `fuzz/support/wal_oracle.hpp` re-implements the WAL
  layout (magic / length / payload / checksum) from scratch, defining its own
  persisted-format magic `kOracleWalMagic` independently (it does NOT include
  `<sluice/wal.hpp>` and does NOT call any production WAL helper). The target
  requires production success **iff** oracle canonical validity (decoded AND
  magic ok AND checksum ok) — bidirectional.
- `wal_roundtrip_fuzz` — validates each writer's emitted bytes against the
  independent canonical-format oracle (magic, declared length, payload equality,
  stored checksum, consumed size, no extra bytes) so common-mode writer/reader
  format drift is detected. Also checks scalar/vector byte identity, production
  decode round-trip, and clean EOF after exactly one record.
- `copy_all_fault_fuzz` — `fuzz/support/copy_model.hpp` provides minimal
  observable Reader/Writer endpoints including a `BufferedReadable` model. The
  oracle runs universal invariants (U1-U7) before any result-specific early
  return, then classifies the terminal result and checks the buffered-path
  invariants (CB1-CB6).

## 4. Mutations are killed (hermetic proof)

`scripts/run-wal-copy-mutations.sh` applies 13 mutations in an **isolated git
worktree** checked out at BASE_SHA and replays the seed corpus **tracked at
BASE_SHA** (via `git -C WORKTREE ls-files`, never `find` over the caller's
worktree). The proof is hermetic:

- **Corpus authority** — every killer exists in BASE_SHA; untracked local seeds
  cannot participate.
- **Baseline preflight** — the unmodified targets build from BASE_SHA and every
  tracked seed replays exit 0 before any mutant is classified. A seed that
  already crashes baseline is BLOCKED, not a killer.
- **Evidence preservation** — every baseline and mutant invocation is captured
  to a per-run log under an evidence directory; a KILLED report records the
  mutant ID, target, seed, exit code, and a concise failure signature + log path.

Baseline preflight:

```

BASELINE wal_roundtrip_fuzz:   PASS (10 seeds)
BASELINE copy_all_fault_fuzz:  PASS (48 seeds)
```

## 6. Proof-chain fixes applied in this corrective

- **Corpus authority (A)**: mutation corpus is taken from the BASE_SHA worktree
  via `git ls-files`, not the caller worktree. Untracked local seeds cannot
  influence the proof.
- **Baseline preflight (B)**: the unmodified targets are replayed over the same
  tracked seeds before any mutant; every baseline pair must exit 0.
- **Evidence preservation (C)**: per-invocation logs replace `/dev/null`;
  KILLED reports carry mutant ID / target / seed / exit code / signature / log.
- **Classification (D)**: KILLED / SURVIVED / INVALID / BLOCKED, so timeouts,
  loader errors, missing seeds, and sanitizer-runtime bootstrap failures are
  never presented as semantic kills.
- **Independent WAL magic (D)**: the oracle defines `kOracleWalMagic`
  independently and no longer includes `<sluice/wal.hpp>`.
- **Valid-frame iff success (E)**: `wal_read_record_fuzz` now requires
  `result.has_value() == oracle_valid` (bidirectional).
- **Canonical writer verification (F)**: `wal_roundtrip_fuzz` validates emitted
  bytes against the independent oracle (closes common-mode drift).
- **Common-mode mutant (M-WAL-06)**: shared checksum algorithm mutation, killed
  by the independent oracle.
- **BufferedReadable coverage (G)**: a `ModelBufferedReader` exercises the
  production buffered fast path; CB1-CB6 invariants checked.
- **Per-request remaining-limit invariant (H)**: U6 checks every scratch read
  against the remaining limit at that moment, on success AND error paths.
- **Corpus origin documentation (I)**: `fuzz/corpus/MANIFEST.md` and the README
  state that the corpus is the union of curated named + SHA-discovered seeds.
- **Distribution and empty-input fixes (J)**: real modulo mapping; safe empty
  `tail()`.
- **No silent truncation (§19)**: the copy harness consumes the complete payload;
  resource bounds live in the runner's target-specific `-max_len`.
- **Zero-progress writer + early clean EOF (§20)**: new model modes and curated
  seeds (`writer_zero_progress`, `early_eof_before_first`,
  `early_eof_after_prefix`).
- **Universal invariants first (§21)**: U1-U7 run before any result-specific
  early return.
- **Clang-only build guard (§11)**: explicit `on_config` guard in `xmake/fuzz.lua`.

## 8. Residual notes / lessons learned

- The mutation set is fixed and hand-authored. It is not an unbounded mutation
  framework. Adding a new production invariant should come with a new mutation
  and a new tracked seed that kills it.
- The fuzz targets are Clang-only; they are not built by other toolchains
  (enforced explicitly by the `xmake/fuzz.lua` guard).
- The committed gate is deterministic exact tracked-corpus replay plus bounded
  smoke. Unbounded/overnight fuzzing is a separate, scheduled activity and is
  not part of CI; its policy (workspace isolation, bounded runs, optimization-
  sensitive replay, GCC ordinary-test diversity, crash handling, minimization,
  stop conditions) is documented in the corrective task and applied only after
  the mandatory gates pass.
- Named semantic seeds are kept even if libFuzzer regards them as coverage-
  redundant; they encode human-readable contract boundaries distinct from
  coverage uniqueness.
