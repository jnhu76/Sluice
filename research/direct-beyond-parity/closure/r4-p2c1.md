## 3. Reviewer Observation 1 — THREAD-01 并发 close 边界

**（a）v2 THREAD-01 合同范围**（读 `docs/explicit-io-contract.md` §13）：
File 的 move/close/destruction 要求**调用方串行化**且"无未决的原生资源借用"；
SEM-03 使准入成为每次公开调用的前置条件。组合进行中并发 close 同时违反两条
——对 C1 基线与本分支**同样**在合同外（两树的每步都在无同步地读取非原子
`fd_`：B1 逐步 `is_open()`+`native_handle()`，本分支逐步 `native_handle()`；
该交错本身即调用方数据竞争 → C++ UB，二者同级）。

**（b）合同内行为一致（证明）**：入口准入是 C1 未改动的同一路径
（`admit_data_op` → `precheck_data_op`，四组合入口 diff 外）；调用方串行化
成立时文件状态在调用期间无法合法变化，逐步重跑准入在合同内不可观测。独立
证据（全部 [RUN]）：

- 套件矩阵（§6）全绿：组合 EOF/短读/无进展/impossible-count/Confirmed Bytes/
  Effect Certainty 义务由既有 oracle 套件 + 7 项具名 mutation 钉住。
- Installed-SDK 消费者探针 16/16（§8）：closed 文件 `read_exact_at` →
  `invalid_state`（含 closed-before-empty 零长度臂）；access-before-empty；
  past-EOF 前缀 + `eof_before_full`。
- strace oracle（§8）：满读 1×`pread64`；31B 请求/23B 文件 = 23B 步 +
  `pread64(...,8,23)=0` EOF 步（每步恰 1 syscall）；零长度 0 syscall；
  closed 0 syscall（入口准入先于任何 native 调用）。

**（c）合同外差异（显式披露）**：调用方违约并发 close 且竞争恰好可见时，
C1 下一步以 `invalid_state` 停机；本分支继续对已关闭描述符 `pread`，
表现为 EBADF 类 `backend_error`（`from_errno_value(EBADF)`→
`canonical_error_code` 不在映射表 → `backend_error`，`os_errno=EBADF`，
读 `include/sluice/error.hpp` 实证）。披露位置：ledger SEM-05 行
"Missing proof or gap"列 + PR #612 正文专节 + 本文件。写侧两组合不受影响
（步原语仍为公开 `write_at`/`write`，逐步准入保留）。

**（d）资源安全/UB/泄漏检查**：`File::close()` 为
`std::exchange(fd_,-1)` 后 `::close(fd)`（`src/file_resource.cpp:104-111`）；
对 −1 描述符 `pread` 是 POSIX 定义的 `EBADF` 错误返回，非崩溃/非未定义
（POSIX 层）；不分配内存 → 无泄漏；`native_handle()` 每步重读、`File` 以
const 引用传入 → 无 UAF（对象生命周期由调用方在两树下同等保证）；fd 复用
误读风险仅存在于调用方数据竞争（UB）前提下，两树暴露等价。结论：合同外
差异不构成本分支引入的新安全缺陷；无真实缺陷被"合同外"标签掩盖。

## 4. Reviewer Observation 2 — Error-Path Dead Store（独立已验证收缩）

- **定位** [RUN]：收缩前 release 对象四组合函数的 primitive_error 出口各含
  2 个 `movq $0` store（`read_exact_at` 0x1059 `0x2a(%rsp)` 与 0x1067
  `0x30(%rsp)`；`write_all_at`/`read_exact`/`write_all` 帧偏移不同、形状相同）。
  与冻结研究披露的 `0x1067` 完全同位。布局实证
  （`offsetof` + 字节 dump 探针，g++ -O2）：`CompositionOutcome` 24B
  {confirmed@0, end@8, remaining@9, optional@12}；libstdc++ `optional<IoError>`
  12B 为 **payload 在前、engaged 在后**（{code@0,pad,errno@4,engaged@8}）。
  故 `movq $0,0x30(%rsp)` 覆盖 os_errno+engaged+pad，其中 os_errno 于
  0x1074、engaged 于 0x1078 被完全覆写，仅语义上不定的 padding 字节存活
  ——dead payload，可安全消除。
- **收缩**（`b12fb551`，+2/−6）：`primitive_error_outcome` 由"默认构造局部 +
  逐字段赋值"改为 `return CompositionOutcome{...}` 聚合初始化。
- **机器级复验** [RUN]：收缩前四实例各 2 个 `movq $0,<x>(%rsp)`（0x2a/0x30、
  0x1a/0x20、0x49/0x4c、0x39/0x3c 系）；收缩后**全部消失**（0 个），替换为
  单条融合存活 store（如 `movq $0x6,0x2c(%rsp)` = code+errno 常量对）；
  errno 分类 cmp 链（EINTR/EACCES/EPERM/ENOENT/ENOTDIR/ENOSPC/EDQUOT/EAGAIN →
  canonical code）逐指令相同 → **Error Mapping 不变**；`error.hpp` 零改动。
- **行为复验** [RUN]：`FAILURE_ACCOUNTED` mutant 在收缩后 head 仍被
  `error_after_confirmed_prefix_keeps_the_prefix` 击杀（钉住错误出口
  remaining=unknown）；全套件 58/58 于收缩后 head 重跑绿。
- 收缩后残留 2 条同值冗余 store（`mov %cl,0x2c`/`mov %eax,0x30`，值与融合
  store 完全相同，GCC 未 CSE）；无任何部分死 store。这是 peephole 层噪音，
  非语义死存，不构成新的披露项。
